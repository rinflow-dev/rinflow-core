# 附属屏幕（KVM 挂在宿主设备上）

## 场景

Mac 控制 Windows，KVM 摆在 Windows 旁边。指针从 Windows 推向 KVM 时应该进入 KVM，画面全屏显示在 Windows 上。以前做不到，有两个原因：
- Mac 的排列里没有 KVM，因为链式摆放不同步；
- Windows 被控时不能再去控制别人。

做法：把 KVM 当作 Windows 的一块**附属屏幕**。
- Windows 告诉其他设备自己有哪些显示器时，把 KVM 也算进去。
- Windows 被控时，把落在这块屏幕上的输入转发给 KVM。

这样做不需要改 Mac，Mac 也不需要和 KVM 配对。排列不共享，也不引入新的信任关系。代码在 [runtime/attached.rs](../src/runtime/attached.rs)。

```
 Mac 看到的 Windows                  Windows 自己的排列
 ┌──────────┐┌──────────┐            ┌──────────┐┌──────────┐
 │ Windows  ││ (KVM)    │            │ Windows  ││ KVM      │  ← 普通的摆放
 │ 显示器   ││ 附属屏幕 │            │ 显示器   ││ (对端)   │
 └──────────┘└──────────┘            └──────────┘└──────────┘
```

## 1. 哪些设备算附属设备

一个对端要同时满足以下条件，才算附属设备：

- **声明了能力位 15 `ATTACHABLE`**：表示它没有自己的键盘鼠标，只会被控制。KVM 用配置键 `attachable` 打开这一位，电脑不打开。
- **直接贴着本机的显示器**：本机摆放了它，而且它贴的是本机自己的显示器。只贴着其他对端的链式摆放不算。
- **会话已建立**：KVM 离线时，这块屏幕就不算附属屏幕了。
- **显示器已知**：它已经告诉过本机自己有哪些显示器。

附属屏幕始终启用，没有开关。

一台 KVM 可以同时挂在几台宿主上。谁在控制它，由 KVM 现有的规则决定：最新的控制者获胜。

## 2. 对外报告

- **`ScreenInfo`**：会话中的对端收到的是本机的显示器，加上各个附属屏幕的显示器（已平移到本机坐标系）。线路格式不变，旧版本的核心看到的只是多了一块显示器。
- **不报告给附属设备本身**：发给 KVM 的 `ScreenInfo` 不含它自己那块，否则 KVM 会看到一块和自己重叠的屏幕。
- **发现广播只含本机的显示器**：KVM 在会话建立之前就可能听到广播。如果广播里有附属屏幕，KVM 会看到宿主和自己重叠，从而把摆放挪开。
- **只有一跳**：别的设备报告给本机的附属屏幕，本机不会再报告出去。
- **同步摆放**：判断一个对端是否贴着本机（`touches_local`）时，附属屏幕也算本机。对端摆在附属屏幕旁边时，同步方式和摆在本机旁边一样。
- **本机的排列不变**：本机自己的吸附和传送门计算照旧，在本机的排列里 KVM 仍然是一个普通的对端。
- **何时重新报告**：以下情况发生后，核心会检查附属屏幕有没有变化，有变化就重新发送 `ScreenInfo`：
  - 摆放变化；
  - 任一端的显示器变化；
  - 会话建立或结束。
- **事件 `attached_screens`**：`{"screens":[{"peer_id":…,"offset":{"x","y"},"displays":[…]}]}`。`displays` 已在本机坐标系里；`offset` 是 KVM 的摆放位置，减去它就得到 KVM 自己坐标系里的坐标。外壳据此判断指针是否进入了附属屏幕。

## 3. 转发

| 接口（ABI 11） | 作用 |
| --- | --- |
| `lc_core_set_relay_target(core, peer_id)` / `Core::set_relay_target(Some(..))` | 开始转发。只接受附属设备，而且本机必须正被控制，否则立即发出 `relay_ended`，原因是 `not attached` 或 `not driven`。 |
| `lc_core_set_relay_target(core, NULL)` | 结束转发。KVM 会收到 `InputReset`，松开所有按住的键；这种结束不发事件。 |
| `lc_core_relay_input(core, event)` / `Core::relay_input` | 把输入发给转发目标，坐标用 KVM 自己的坐标系，最好是绝对位置。没有转发目标时输入被丢弃。 |

规则：

- **走已有的会话**：转发的输入走本机和 KVM 之间已有的会话，序号和按键跟踪也是同一套。在 KVM 看来，就是 Windows 在控制它，所以 KVM 端不用改。转发和外壳自己的输入排在同一个队列里，但不会互相合并。
- **不算控制别人**：转发不撤销控制本机的设备，也不设置 `controlling`，也不同步剪贴板。
- **控制者停止，转发就结束**：转发和开始转发时控制本机的那个会话绑定。这个会话一旦不再控制本机，核心就结束转发，给 KVM 发 `InputReset`，并发出 `relay_ended`（原因 `control ended`）。不再控制的情况包括：对方复位、被撤销、断线、被别的设备接管。
- **KVM 被别人接管**：KVM 撤销本机的控制时，只结束转发，`relay_ended` 的原因是 `revoked`，控制本机的设备照常控制。外壳再次调用 `set_relay_target` 时可以把 KVM 抢回来，仍然是最新的控制者获胜。
- **附属屏幕消失**：转发结束，原因是 `not attached`。
- **本机用户推进 KVM**：本机用户用自己的键鼠推进 KVM 时，按原来的规则处理：撤销控制本机的设备，转发随之结束，改为本机直接控制 KVM。

所有原因都有 `reason_code`：`control_ended`、`not_attached`、`not_driven`、`revoked`。

## 4. 控制权规则

[architecture.md](architecture.md) 里"一次只有一个控制者"那一条加了一个例外：附属屏幕算宿主自身的一部分，宿主被控时可以把输入转发给附属设备。

## 5. 信任边界

能控制 Windows 的设备，就能经由 Windows 控制挂在它上面的 KVM，即使它没有和 KVM 配对。这正是这个功能要的效果。其他边界不变：
- KVM 只接受和它配对过的设备（这里是 Windows）；
- Mac 和 KVM 之间没有任何连接。

## 6. 外壳要做的（Windows）

- **被控时跟踪指针**：注入的是相对移动，Windows 的真实光标会停在显示器边缘，所以注入端要自己记一个虚拟指针。满足以下条件时，进入转发：
  - 光标在贴着附属屏幕的那条边上；
  - 移动继续往外推；
  - 而且推出去的位置落在两块屏幕相接的那一段。

  对方发来的绝对位置（落点）如果直接落在附属屏幕上，也进入转发。
- **转发中**：
  - 虚拟指针限制在附属屏幕内，换算成 KVM 坐标系里的绝对位置后发出；
  - 按键、按钮和滚动原样转发；
  - 真实光标停在出发点并隐藏；
  - 全屏画面显示在出发的那块显示器上。
- **离开**：虚拟指针越过相接的那一段回到本机时，调用 `set_relay_target(NULL)`，把真实光标放到对应位置，并退出全屏。收到 `relay_ended` 或 `remote_control_ended` 时也一样退出。
- **Mac**：不用改。

## 7. 边界情况

- **Mac 自己也摆了这台 KVM**：两条路都能用，由 KVM 按最新控制者获胜裁决。
- **KVM 的分辨率变了**：KVM 照常发 `ScreenInfo`，宿主重新报告附属屏幕。
- **Mac 只贴着附属屏幕**：在 Windows 的排列里，这是 Windows → KVM → Mac 的链式摆放，现有规则已经支持。不过 KVM 离线时，这块屏幕会从 Windows 的显示器里消失，Mac 会把 Windows 重新吸附到别的位置；KVM 回来后，不会自动恢复原来的位置。
- **KVM 上线后撞到别的设备**：KVM 上线后，Mac 看到 Windows 变大了。如果多出来的那块和 Mac 排列里的其他设备重叠，Mac 会按显示器变化的规则重新吸附 Windows。
- **只认一跳**：附属设备不能再带附属设备，也不能经由附属设备链式挂接，只认直接贴着本机的那一跳。

## 8. 版本

- **C ABI 仍是 11**，在 11 之内新增：
  - 配置键 `attachable`；
  - `lc_core_set_relay_target` 和 `lc_core_relay_input`；
  - 事件 `attached_screens` 和 `relay_ended`。
- **线路协议仍是 v4**，只增加了能力位 15，旧版本照常互通。
- **`rinflow-nanokvm`**：在配置里设 `attachable: true` 即可。

## 9. 测试

在 [lib.rs](../src/lib.rs) 里：

- **`an_attached_screen_counts_among_its_hosts_displays_for_other_peers_only`**：
  - Mac 看到宿主有两块显示器，KVM 从来看不到自己；
  - 摆放移除后，附属屏幕消失，Mac 看到的也恢复成一块。
- **`a_driven_host_relays_to_its_attached_screen_without_giving_up_control`**：
  - 没人控制宿主时，转发被拒绝；
  - 被控时转发成功，而且不会撤销 Mac；
  - 别的设备接管 KVM 时，只结束转发；
  - 再次转发可以把 KVM 抢回来；
  - Mac 复位后，转发结束，KVM 被松开；
  - 宿主本机用户推进 KVM 时，Mac 被撤销。
